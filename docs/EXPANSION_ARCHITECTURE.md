# エリア・駅を追加する手順

## 表示側のファイル

- `data.js`：対応駅全体の表示範囲と地下鉄の線路概観。坂・出口・構内形状は入れない。
- `data/area-index.json`：区画の位置、URL、容量。緯度0.009度・経度0.011度で、東京では約1km四方。
- `data/areas/*.json`：道路、坂、出口標高、地下鉄のホーム・通路・出口。線は区画境界で切り分ける。面は元形状を保持し、読み込み時に重複を除く。各ファイル3MB未満を生成時に検査する。
- `data/station-index.json`：駅名、路線、代表座標、収録件数、階、注意事項、駅別JSONのURL。
- `data/stations/*.json`：その駅の構内GeoJSONと来歴。選択した駅だけを取得する。

`area-loader.js` は表示範囲と交差する区画を同時4件まで読み、移動後は画面外のデータを描画から外す。使っていない区画のキャッシュは原則16区画まで。表示範囲自体が広い場合は必要な区画を保持する。古い通信が後から届いても、新しい表示範囲に上書きしない。

`station-interiors.js` は路線から駅を絞り、駅別JSONを読む。最大6駅をキャッシュする。駅を連続して変更したときは最新の選択だけを描画する。取得失敗とOSMの未収録は別の表示にする。

同梱背景タイルは増やさない。画面が同梱範囲をはみ出すと、OpenFreeMapのオンラインスタイルへ切り替える。キーは不要。オンライン背景の取得に失敗したときは同梱背景へ戻り、範囲外は背景が空白になる。JSONの読み込みがあるため、`file://` ではなくHTTPで開く。

## 新しい駅を加える

Python 3、numpy、Pillowを使う。仮想環境に必要なものを入れる例：

```sh
python3 -m venv .venv
.venv/bin/pip install numpy Pillow
```

駅リストの形式：

```json
{"stations":[{"id":"osm-6227812517","name":"六本木一丁目","pos":[35.6649588,139.738939],"lines":["南北線"]}]}
```

座標はOSMの駅・停止点から採る。`id` は他駅と重ならない、ファイル名に使える値にする。リストを `data/` に保存して次を実行する。

```sh
.venv/bin/python data/build_area.py --stations-file data/station-list.json
```

登録済みの一部の駅だけを処理する場合：

```sh
.venv/bin/python data/build_area.py --stations 東京 渋谷
```

1駅ずつ、周辺約800mの外接矩形からOSMの道路・駅施設を取得し、国土地理院DEM1A、欠測時はDEM5Aで標高を読む。道路を約5m間隔に分け、5点平均後の約20m区間で勾配を計算する。橋・地下・屋内等を坂の計算から除く。4%以上を表示し、幹線道路12%超・その他25%超を誤差候補として除く。出口標高は出口位置の地表値で、地下の床の高さではない。

OSMのwayは矩形と交わる道路の全形状を返すため、取得範囲の端では道路と坂が矩形外へ延びる場合がある。新しい駅を足すと、その駅周辺の道路・坂・出口も共通の区画へ入り、地図の収録範囲が広がる。

駅リストの指定を省略した場合は、`data/station-list.json` を使う。現在の96駅群のリストは `data/station-list.json`。生成済みの駅は通常スキップする。取得失敗はログへ残して次の駅へ進む。同じコマンドを再実行すると、失敗した駅から取得を続ける。Overpassは直列・最小10秒間隔、失敗後は少なくとも30秒空ける。既定の接続先はVK Mapsの公開Overpass。別の公開接続先を使う場合は `--endpoint URL` を指定する。取得処理はPOSTを使う。

東京メトロ・JR・都営の駅列挙には `data/discover_metro.py`・`data/discover_jr.py`・`data/discover_toei.py` を使う。保存した路線・停止点・駅カタログを統合する。東京メトロとJRの中間リストは非公開の `data/raw/expansion/metro-stations.json`・`metro-jr-stations.json` に保存し、都営の列挙で全96駅群の `data/station-list.json` を出力する。別名の乗換駅は `aliases` と元の `members`・`member_positions` を残して1駅にする。統合は一覧の編集規則であり、構内接続・改札内外は未検証と画面にも表示する。原宿／明治神宮前、御徒町／上野広小路・仲御徒町などの別名も照合する。

駅ごとの問い合わせを減らす場合は `--shared-facilities` を付ける。全対象駅の矩形を覆う共通施設入力を1回取得し、各駅の道路入力と組み合わせる。成功済みの共通施設入力があれば、通常の再開・`--rebuild`でも同じ入力を再利用し、駅別施設を取り直さない。原入力の取得範囲外では駅別取得を行う。

生成済みでも路線・順序・別名・停止点が変更された駅は保存済み原入力から再生成する。構内の駅所属は統合駅内の各路線の停止点も使う最近接推定。統合前の駅JSON・キャッシュは来歴として保持し、画面の索引からは旧名を外す。周辺道路・坂は保持し、出口は現在の索引にある駅のキャッシュから生成する。

駅自身の成功入力がない場合、既存の全種別OSM入力の矩形を調べ、駅周囲の矩形全体を覆える場合だけ再利用する。道路専用入力を再利用する場合は、道路と施設の充足を分けて検査する。道路の矩形全体を保存済み入力で覆えれば、施設だけを別の原入力から読み込む。候補矩形の境界で分割した全小矩形に入力があることを検査し、わずかな穴も許容しない。元クエリと同じ範囲内ノード／頂点を持つwayを抽出し、原形状は保持する。使用した全原入力を駅JSONの `raw_sources` に列挙する。完全に覆えない場合は追加取得し、未取得範囲を推測で補わない。複数プロセスを誤って起動した場合も、Overpass取得は排他ロックで直列化する。

大きな範囲の取得だけが繰り返し失敗するときは、同じ範囲を4分割し、道路・施設も分けて小さく取得できる。各原レスポンスを別保存し、駅JSONの `raw_sources` に列挙する。形状・タグは元の要素を保持し、重複IDだけをまとめる。例：

```sh
.venv/bin/python data/build_area.py --stations 池袋 --split-query
```

駅全体を覆う共通施設の成功入力がある場合、4分割では道路だけを追加取得し、施設はその共通入力を再利用する。共通入力が駅全体を覆わない場合は各小矩形の施設も取得する。

一部が取得できた後は、通常の再実行でも残りの分割入力を再開する。実行時間・メモリ指定だけが違う保存済みクエリは同じ抽出条件として再利用し、実際に取得したクエリの記録を保持する。

保存済み入力で駅構内・勾配も作り直す場合：

```sh
.venv/bin/python data/build_area.py --rebuild --stations-file data/station-list.json
```

`--rebuild` は保存済みOSM・DEMを再利用する。入力クエリを変える場合は、生データを黙って置き換えず、新しいIDまたは退避先を用意する。

駅別計算キャッシュの道路・坂・出口と地下鉄概観を区画化する場合は、標準Pythonだけで実行できる。

```sh
python3 data/build_bundle.py
```

## 生データと判定の限界

`data/raw/expansion/` にOverpassの原JSONをgzipで保存する。圧縮以外は変更しない。クエリ、接続先、取得日時、OSM基準時刻、原レスポンスのSHA-256を隣のファイルに残す。DEMの原PNG、URL、取得日時、SHA-256、404の記録も `dem/` に置く。一時的な通信障害は恒久的な欠測として保存しない。

`data/processed/` は再計算用の圧縮キャッシュ。構内の原タグは駅別JSONと原レスポンスへ保持する。表示用の駅別JSONは `data/station-index.json` を正本の索引とする。

駅所属は周辺駅代表点から450m以内の最近接による推定を含む。商業施設の地下通路などが混ざる可能性がある。駅構内全体、接続、改札内外、路線の全設備を保証しない。バス停のplatformは鉄道ホームに数えない。路線色は元タグまたはOSM路線メンバーで確認できる場合のみ使い、未確認のホームは灰色にする。

階は元の `level` 値を保持する。`-1;-3` を途中の `-2` へ補完しない。階がない設備の地下深さを推測しない。立体表示の深さと出口接続は模式・推定として表示する。OSMに形状がない設備、結合していない面リレーション、公式構内図の形状は補わない。

山手線内の判定はOSM山手線の順序付き停止点を結ぶ多角形と、同名の境界駅の照合で行う。線路の曲線や駅敷地の境界とは異なる。丸ノ内線の池袋は路線リレーションのstopメンバーが欠けていたため、終点タグとOSMの同名・同路線番号M25の駅ノードを照合した。判定用入力と現在の駅リストに除外駅の記録を残す。

## JRの入力と模式階

JRは山手線30駅と内側7駅を登録し、同名・別名の地下鉄駅を統合する。JRの選択路線は山手線、中央・総武線、中央線快速の3系統。別のJR系統が乗り入れる駅も駅としては含むが、その全系統の路線別一覧は作成していない。

JRの列挙には `data/discover_jr.py` を使う。判定用の駅・停止点カタログは35.60,139.67,35.75,139.79の外接矩形（山手線の停止点多角形を完全に含む）。停止点の矩形外に伸びる中央線・総武線の路線relationも原データとして保存し、取得していない範囲外停止点IDは駅リストへ記録する。駅選択は山手線の停止点多角形と山手線駅名で判定する。

ホームの地上/高架の補助入力は `jr-platform-tracks.json.gz`（OSM線路形状・タグ）。同路線のrouteに所属する30m以内の最寄り線路にトンネル・地下タグがなければ地上として推定する。階未収録または負階のJRホームに限り、地上0、高架は模式的な1を表示階に使い、`level_raw` と `original_tags` は無変更で残す。高架判定はbridgeタグまたは正のlayer。layerを実際の階数として解釈しない。`level_method`・`level_note`・`surface_context` に根拠を保存し、画面でも模式/推定と原levelを示す。地下・同路線線路なし・30m超は階を補わない。切通しの負の原levelを地上基準へ表示する場合も、周囲の道路との実際の高低差は再現しない。

立体表示は負階を地下、0以上を地面の上に描く。level 0は見やすさのため4m浮かせる。階間5m×誇張倍率は実測床高ではない。点のEVと跨階階段、地上/上層に接続する出口にも対応。出口のlevel 0自体は構内への接続階の根拠にしない。既知の最寄り設備から接続を推定し、表示で明記する。

共通施設入力は `jr-shared-facilities`、`metro-shared-facilities` の順に取得範囲を照合して再利用する。保存済み原入力で矩形全体を覆えない新規駅だけ道路等を追加取得する。問い合わせの連続失敗時は待機時間を延ばし、成功済み原入力・生成済み駅を保持する。取得失敗は未収録として扱わない。

路線のplatformメンバー参照が欠けているJR駅では、階未収録・train=yesのホームに限り、10m以内のJR線路から地上/高架の模式階を推定する。地下鉄タグ・負のlayer・既知の別路線所属は対象にせず、路線所属そのものや路線色は補わない。画面では路線所属未確認と明示し、surface_context.associationで同路線確認済みの推定と分ける。

駅ごとの収録状況は [全駅の収録状況](STATIONS_COVERAGE.md) を参照する。信濃町はホームlevel未記載で、近傍の同路線線路にtunnel=yesがあるため、地上階を補わない。画面では階未収録と表示し、立体表示からは省く。

## 全96駅群と収録表の再生成

`data/station-list.json` が東京メトロ・JR・都営を含む現在の駅リスト。浅草線・三田線・新宿線・大江戸線のOSM路線を山手線の停止点多角形と境界駅名で判定する。全方向と新宿線急行を照合し、同じrefのS-TRAINはnetworkタグで除外する。保存済みの停止点・駅カタログを再利用し、不足停止点のみ小分けに取得する。取得失敗を設備未収録と解釈しない。

同名駅と近接する別名乗換駅は一覧で統合し、既存ID・路線・元停止点を保持する。統合規則は `data/discover_toei.py` の `MERGES`、対象外駅は正本の `toei_excluded`。泉岳寺と高輪ゲートウェイは別駅群のまま。構内接続・通行可否は補わない。駅の表示順はOSMの駅番号を基本に、番号のない駅だけ全駅停車routeの前後の番号から順序を求める。位置・階・形状の補間には使わない。

```sh
python3 data/discover_metro.py
python3 data/discover_jr.py
python3 data/discover_toei.py
python3 data/build_area.py --rebuild --stations-file data/station-list.json
python3 data/build_coverage.py
python3 tests/check_toei.py
```

numpy/Pillow環境を使用する。Overpassは直列・最低10秒間隔。混雑時は待機を延長する。成功原入力は再取得・上書きしない。駅の所属が変わるため、全駅を更新する場合は全駅を再生成して地物の重複所属を検査する。

全駅群の件数・未収録は [STATIONS_COVERAGE.md](STATIONS_COVERAGE.md) に記載する。原入力を使う検証には、非同梱の `data/raw/` が必要。
